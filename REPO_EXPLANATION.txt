IMPORTANT — RUNTIME REQUIREMENTS
---------------------------------
This project was developed and executed inside Docker containers on a local
laptop, with network hooks to the OpenAI API via a LiteLLM proxy.

To reproduce results you would need:
  1. Docker Desktop  — Neo4j runs as a Docker container (dsc288-neo4j)
  2. OpenAI API key  — All LLM calls (analyst agent, LLM judge, embeddings)
                       go through LiteLLM → OpenAI. The models used include
                       gpt-5.2-chat, gpt-5-mini, gpt-5-nano, and others.
  3. Python 3.10+    — With packages from requirements.txt
  4. Finnhub API key — Only needed if re-downloading raw stock data

THE CODE WILL NOT RUN WITHOUT VALID OPENAI API KEYS.
API keys are stored in a .key file at the repo root (gitignored) with the
format OPENAI_API_KEY=sk-... (one KEY=VALUE per line).

The included results, evaluation outputs, figures, and HTML report represent
our completed evaluation outputs and can be reviewed without running anything.

================================================================================
WHAT THIS PROJECT IS
================================================================================

A multi-agent LLM-based system that gives retail investors buy/hold/sell
recommendations on stocks, with natural-language explanations grounded in
real financial data via Graph RAG (Retrieval-Augmented Generation backed by
a Neo4j knowledge graph).

The key innovation is EXPLAINABILITY — not just a prediction, but a cited,
structured explanation of why the model recommends buy, hold, or sell. The
system uses specialized agents and a knowledge graph of real Finnhub data
(earnings, news, analyst recommendations, peer networks) to produce
recommendations that can be traced back to specific data points.

Target users: intermediate/beginner retail investors who value understanding
financial recommendations over opaque numerical predictions.

================================================================================
DATA PIPELINE  (5 stages)
================================================================================

Run the full pipeline:
  python scripts/run_pipeline.py

Or run stages individually:
  python scripts/01_load_data.py
  python scripts/02_clean_data.py
  python scripts/03_align_data.py
  python scripts/04_feature_engineering.py
  python scripts/05_merge_and_split.py

--- STAGE 1: LOAD DATA  (scripts/01_load_data.py) -----------------------------
- Loads FNSPID prices (individual CSVs per ticker)
- Uses Finnhub/Neo4j ticker list when available; intersects with FNSPID so
  train/val/test align with Neo4j for evaluation
- Loads FNSPID news, Financial Phrasebank, Yahoo S&P 500, FinQA
- Saves selected ticker list to data/processed/selected_tickers.json
- Outputs: data/processed/*_raw.parquet, 01_loading_summary.json

--- STAGE 2: CLEAN DATA  (scripts/02_clean_data.py) ---------------------------
- Prices: standardize columns, forward-fill, drop duplicates, remove outliers
  (>50% daily change — justified as data errors in curated universe)
- News: detect columns, strip HTML, remove short/empty/duplicate articles
- Phrasebank: dedupe, standardize labels
- S&P 500: standardize dates, compute sp500_return
- Outputs: data/processed/*_clean.parquet, 02_cleaning_summary.json

--- STAGE 3: TEMPORAL ALIGNMENT  (scripts/03_align_data.py) --------------------
- Filters prices to news-available period (Oct 2009 – Dec 2023)
- Aggregates news by (ticker, date); counts articles per stock-day
- Left-joins news onto prices (keeps all price rows)
- Joins S&P 500 market context
- Creates next_day_return and buy/hold/sell targets (fixed ±2% thresholds)
- Outputs: data/processed/data_aligned.parquet, 03_alignment_summary.json

--- STAGE 4: FEATURE ENGINEERING  (scripts/04_feature_engineering.py) -----------
- Per-ticker indicators: SMA-5/20/50, momentum-5/20, volatility-20,
  volume ratio, price-to-SMA ratios
- Market features: excess return, market_up/market_down indicators
- Drops first 50 rows per ticker (warm-up for SMA-50)
- Normalization intentionally deferred to Stage 5 (no leakage)
- Outputs: data/processed/data_engineered.parquet

--- STAGE 5: SPLIT + NORMALIZE  (scripts/05_merge_and_split.py) ----------------
- Temporal split (no shuffling):
    Train:      everything up to 2021-12-31
    Validation: 2022-01-01 to 2022-12-31
    Test:       2023-01-01 onward
- Normalization (fitted on TRAIN split only):
    MinMaxScaler for prices → *_norm columns
    StandardScaler for volume and returns
- Forward-fill applied independently per split (no cross-split leakage)
- Creates RAG context file for Graph RAG retrieval
- Outputs:
    data/processed/train_final.parquet   (2009–2021, ~129K rows)
    data/processed/val_final.parquet     (2022, ~14K rows)
    data/processed/test_final.parquet    (2023, ~6K rows)
    data/processed/rag_context.parquet   (news text for retrieval)

================================================================================
NEO4J KNOWLEDGE GRAPH (Fin Memory)
================================================================================

Finnhub data is ingested into a Neo4j graph database for Graph RAG. The
graph provides structured financial context that the LLM agents query when
generating explanations.

Entities:
  - Sector (3): Finance, Semiconductor, Biotech
  - Stock (60): ticker, name, industry, market_cap
  - Earnings (220): period, actual, estimate, surprise, surprise_percent
  - NewsArticle (6,960): headline, summary, source, url, datetime
  - Recommendation (232): buy, hold, sell, strongBuy, strongSell, period

Relationships:
  - Stock -[:IN_SECTOR]-> Sector
  - Stock -[:HAS_EARNINGS]-> Earnings
  - Stock -[:MENTIONED_IN]-> NewsArticle
  - Stock -[:HAS_RECOMMENDATION]-> Recommendation
  - Stock -[:PEERS_WITH]-> Stock

How to ingest (requires Docker for Neo4j):
  python scripts/ingest_fin_memory.py          # start Neo4j + full ingest
  python src/agents/fin_memory.py memorize     # ingest all 60 tickers
  python src/agents/fin_memory.py stats        # graph node/edge counts
  python src/agents/fin_memory.py query "MATCH (s:Stock) RETURN s LIMIT 5"

Neo4j connection: bolt://localhost:7687 (user: neo4j, pw: dsc288graph)
Configuration: config/neo4j.yaml

Documentation: reports/FIN_MEMORY_IMPLEMENTATION.md
Browser queries: reports/NEO4J_BROWSER_QUERIES.md

================================================================================
AGENT SYSTEM (src/agents/)
================================================================================

The multi-agent system consists of specialized modules that work together:

1. graph_context.py  — Neo4j Context Retriever
   Fetches structured context for a ticker from Neo4j: company profile,
   sector, earnings history, news headlines, peer network, and latest
   analyst recommendation. This context is injected into LLM prompts so
   that explanations are grounded in real data.

2. data_context.py  — Market Data Provider
   Loads processed parquet data (val/test splits). Provides rows by
   (ticker, date) for prompt construction and samples for judge evaluation.
   Manages the Finnhub ticker list from _sector_index.json.

3. prompt_builder.py  — Prompt Construction
   Builds prompts for both the analyst LLM and the LLM judge:
   - Analyst prompts: combine Neo4j context + market data, request
     a BUY/HOLD/SELL recommendation with explanation
   - Three prompt variants: "standard", "earnings_focus", "news_focus"
   - Judge prompts: provide context + model output for scoring

4. llm_judge.py  — LLM-as-Judge Scoring
   Uses GPT-5.2-chat as a judge to score analyst outputs on four dimensions:
     - Faithfulness (1-5): does the explanation only use provided data?
     - Relevance (1-5): is the explanation relevant to the recommendation?
     - Consistency (1-5): is the reasoning internally consistent?
     - Correctness (1-5): does the recommendation match ground truth?
   Connects to LiteLLM proxy (localhost:4000). Supports sync and async.

5. fin_memory.py  — Neo4j Ingestion CLI
   Reads Finnhub JSON files from data/raw/finnhub_stocks/ and MERGEs them
   into Neo4j (idempotent). Creates sectors, stocks, earnings, news,
   recommendations, and peer relationships.

================================================================================
EVALUATION PIPELINE (src/evaluation/)
================================================================================

The evaluation system measures both recommendation accuracy and explanation
quality using an LLM-as-judge approach.

1. explainability.py  — Main Evaluation Pipeline
   Commands: build, run, export, all

   "build" — Constructs prompts from Neo4j context + processed data for
   train and test splits, with three prompt variants per sample.
   Output: data/eval/prompts_train.jsonl, prompts_test.jsonl

   "run" — For each prompt: calls the analyst LLM (via LiteLLM),
   parses the BUY/HOLD/SELL recommendation, calls the LLM judge for
   scoring. Computes classification metrics (accuracy, balanced accuracy,
   macro F1) and judge score averages. Generates confusion matrices,
   judge score distributions, and sector accuracy plots.
   Output: data/eval/results_*.jsonl, reports/eval_summary.json,
           assets/figures/eval/*.png, assets/eval_summary_embed.js

   "export" — Extracts demo data from test results for the HTML report.
   Output: assets/demo_data.json, assets/demo_embed.js (or demo_hp_embed.js)

2. hyperparam_sweep.py  — Hyperparameter Tuning
   Sweeps over: prompt strategy (standard vs chain-of-thought),
   max_tokens (300, 500, 800), model (gpt-5.2-chat, gpt-5-mini, gpt-5-nano),
   and temperature.
   Finds best configuration and saves results.
   Output: reports/hyperparam_results.json

   Best configuration found: gpt-5.2-chat + chain-of-thought + 300 tokens
   (10 pp accuracy improvement over baseline)

3. classification_eval.py  — Classification Metrics
   Computes macro F1, per-class precision/recall, and confusion matrices
   for val/test splits. Includes hold-only and majority-class baselines.

Supporting scripts for evaluation:
  scripts/generate_hp_comparison_plots.py  — baseline vs HP-tuned plots
  scripts/generate_hp_demo_data.py         — HP-tuned demo data for HTML

SERVER INFRASTRUCTURE (src/server/)
================================================================================

1. LiteLLM Proxy  (src/server/_serve.py, managed by manage.py)
   A local proxy on port 4000 that routes all OpenAI API calls through
   LiteLLM. Provides model aliasing, caching, retries, and rate limiting.

   Configured via config/litellm_config.yaml:
     - GPT-5 family: gpt-5.2, gpt-5.1, gpt-5, gpt-5-mini, gpt-5-nano
     - O-series reasoning: o4-mini, o3, o1
     - Embeddings: text-embedding-3-small/large, ada-002
     - Project aliases used by agents:
         agent-reasoning → gpt-5.2     (decision synthesizer)
         agent-fast      → gpt-5-mini  (individual agent tasks)
         agent-bulk      → gpt-5-nano  (bulk scoring)
         embedder        → text-embedding-3-small

   Server management:
     python src/server/manage.py start         # start LiteLLM + Neo4j
     python src/server/manage.py start neo4j   # start only Neo4j (Docker)
     python src/server/manage.py status        # check if running
     python src/server/manage.py test          # run test suite
     python src/server/manage.py models        # list available models
     python src/server/manage.py stop          # shut down

2. MCP Server  (src/server/mcp_server.py)
   Exposes financial analysis tools to Cursor IDE via MCP (Model Context
   Protocol). Implemented tools:
     - analyze_stock:       full LLM analysis on a ticker (graph context
                            + analyst LLM + recommendation)
     - evaluate_model:      classification metrics for a split
     - evaluate_with_judge: LLM-as-judge on sampled rows
     - search_news:         search Neo4j news for a ticker
   Placeholder tools (not yet wired): get_sentiment, technical_snapshot,
   backtest

================================================================================
KEY EVALUATION FINDINGS
================================================================================

Classification (test set, 50 prompts):
  - Accuracy: ~60% (test), ~52.5% (train)
  - Macro F1 is low due to strong BUY bias — the model predicts BUY for
    nearly all inputs regardless of ground truth
  - Balanced accuracy reveals this is effectively a majority-class classifier

Explanation Quality (LLM judge, 1-5 scale):
  - Relevance: 4-5 (explanations are on-topic)
  - Consistency: 4-5 (reasoning is internally coherent)
  - Faithfulness: ~1.0-1.3 (critically low — model hallucates specific
    numbers and statistics not present in the provided context)
  - This is the most important finding for production deployment

Hyperparameter Tuning Impact:
  - Best config: Chain-of-Thought prompt + 300 max_tokens (gpt-5.2-chat)
  - +10 percentage point accuracy improvement over baseline
  - Explanation quality preserved; only consistency drops modestly (-0.5)
  - Faithfulness remains low across all configurations — prompt engineering
    alone cannot fix hallucination; requires RAG constraints or citation
    enforcement

Sector Patterns:
  - Semiconductor: highest training accuracy (BUY signals from earnings/sentiment)
  - Biotech: most variable (binary clinical trial outcomes)
  - Finance: HOLD ground truth + BUY bias = frequent misclassification
